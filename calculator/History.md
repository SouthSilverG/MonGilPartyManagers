# 몬길 STAR DIVE 과금 계산기 - 작업 히스토리

## 2026-09-23 최초 제작

### 배경
기존 "몬길 스타다이브 파티 에디터" 저장소에, 사용자가 업로드한 구글시트/엑셀 기반 과금 계산기
("몬길 STAR DIVE 과금 계산기.xlsx")를 동일한 방식(깃허브 페이지)으로 배포되는
웹페이지로 변환했습니다. 기존 저장소에 `/calculator` 서브폴더로 통합했습니다
(파티 에디터 → 계산기, 계산기 → 파티 에디터 양방향 이동 버튼 포함).

### 반영한 요구사항
- **체크박스 실동작**: 원본 엑셀에서는 "구매유무"가 텍스트로 풀려 있었지만,
  원본 구글시트 기준으로는 실제 체크박스였습니다. 웹 버전은 진짜 `<input type="checkbox">`로
  구현했고, 체크한 상품의 가격만 상단 "총합 과금액"에 실시간으로 합산됩니다.
- **계산용 열(G/H/I/J) 비노출**: 원본 시트의 G(뽑기권 환산 총합)/H(재화 합계)/I(재화→뽑기권 환산)/J(선택권 환산)
  열은 화면에 전혀 보여주지 않고, 내부적으로만 계산에 사용합니다(코드상 `calcTicketTotal` 함수).
- **효율 계산 기준**: "3000원당 1뽑"을 기준으로 효율(%)을 계산합니다
  (`효율 = 티켓 환산 총합 × 3000 / 가격 × 100`).
- **향후 유지보수 편의성 (핵심 요구사항)**: 나중에 상품이 추가되거나 가격/보상이 바뀔 때,
  `calculator/data.js` 안에서 **가격**과 **원본 보상 6종**
  (운명의 나침반 `destiny`, 기억의 나침반 `memory`, 약속의 나침반 `promise`,
  태초의 별 `star`, 별빛 수정 `crystal`, 선택권 `choice`)**만** 입력하면 됩니다.
  티켓 환산, 재화→뽑기권 변환, 효율(%) 계산은 전부 `calculator/app.js`에서
  자동으로 계산되며, UI에는 최종 효율(%)만 노출됩니다. 계산용 값을 수동으로
  다시 입력하거나 화면에 표시하는 부분은 전혀 없습니다.

### 데이터 구조 (calculator/data.js)
- `CONFIG`: 재화→티켓 환산 배율(160재화 = 1티켓), 1뽑 기준가(3000원),
  선택권 환산표(5성 캐릭터 = 90뽑, 5성 아티팩트 = 80뽑), 효율 등급 구간(빨강/노랑/초록/파랑)을 정의.
- `SECTIONS`: 원본 시트의 10개 섹션(월정액, 패스, 기록의 정원, 상시 패키지, 스텝업,
  픽업 캐릭터 한정 팝업 패키지, 여정의 궤적, 태초의 별(첫 구매/웹 상점), 깡트럭)을
  그대로 옮겨, 각 상품의 이름/타입/가격/구매 제한/보상 6종을 입력.
- 일부 상품은 "구매 여부" 체크가 의미 없는 참고용 대안 행이라 `checkable: false`로 표시하여
  체크박스 없이 효율만 보여줍니다
  (예: "[픽업 캐릭터] 운명 선택 상자 (캐릭터 등장 시)", "[픽업 아티팩트] 특급 상자 (무기뽑 20개 선택)").

### 중요 설계 결정: "총합 효율" 세트 완료 보너스
원본 시트의 "총합 효율" 행(레나의 스타터 지원 보상 총합/II)은 단순히 그룹 내
개별 상품의 보상을 더한 값이 아니라는 것을 재확인했습니다. **세트를 전부 구매했을 때만
추가로 지급되는 별도의 완료 보너스**(예: 5성 캐릭터 선택권 1장)가 더해져 있었습니다.
이를 개별 상품 데이터만으로는 유도할 수 없어서, `data.js`의 `summaryRow(name, bonusRewards)`에
두 번째 인자로 이 보너스를 명시적으로 입력하도록 설계했습니다.
`app.js`의 `buildSummaryItem(name, group, bonus)`는 그룹 내 상품들의 가격/보상을
자동으로 합산한 뒤, 이 보너스를 추가로 더합니다.

**향후 비슷한 세트(묶음 구매 시 추가 보상이 있는 경우)를 추가할 때는:**
1. 해당 그룹의 개별 상품들을 평소처럼 `SECTIONS`에 나열
2. 그룹 마지막에 `summaryRow("총합 효율 이름", { destiny: N, memory: N, ... })` 형태로
   "세트 전체 구매 시에만 추가로 받는 보상"을 bonus로 지정
3. 만약 완료 보너스가 없는 순수 합산이라면 `summaryRow("이름")`처럼 두 번째 인자를 생략(빈 보너스로 처리됨)

### 검증
- `openpyxl`로 원본 엑셀 파일의 실제 수식/캐시값/조건부 서식 색상을 역추출하여
  효율(%) 계산 로직과 색상 등급 구간을 정확히 재현했습니다.
- Playwright로 다음을 확인했습니다:
  - 체크박스 클릭 시 상단 총합 과금액이 정확히 갱신됨
  - 여러 상품의 효율(%)이 원본 시트의 F열 값과 정확히 일치함
    (예: 퍼스트 클래스 196.15%, STAR DIVE IV 1320.00%, 태초의 별 첫 구매 127.63% 등)
  - "총합 효율" 두 행이 완료 보너스를 반영한 뒤 원본 시트 값과 정확히 일치함
    (레나의 스타터 지원 보상 총합 효율 ₩50,300 / 812.07%,
    레나의 스타터 지원 보상 II 총합 효율 ₩53,400 / 662.92%)
  - `checkable: false`로 지정한 2개 행 + 총합 효율 2개 행, 총 4개 행에만
    체크박스가 없고 나머지 58개 행에는 체크박스가 정상적으로 존재함
  - 페이지 레이아웃(PC/모바일 반응형)이 정상적으로 표시됨

### 향후 상품 추가/변경 방법
`calculator/data.js`를 열어 원하는 섹션의 배열에 아래 형태로 한 줄 추가/수정하면 됩니다.

```js
{ name: "상품명", type: "타입", price: 가격, limit: 구매제한횟수 또는 null,
  rewards: R({ destiny: 0, memory: 0, promise: 0, star: 0, crystal: 0, choice: null }) },
```

가격과 보상 6종 외에는 아무것도 수동으로 입력하거나 계산할 필요가 없습니다.
효율(%)과 색상 등급은 페이지를 열 때 자동으로 계산됩니다.


## 2026-10-14 선택 상품 획득량 및 총합 효율

- 총 과금액 옆에 태초의 별, 별빛 수정, 운명/기억/약속의 나침반 합계를 표시한다. 선택이 없으면 획득량 0, 효율은 -로 표시한다.
- 총합 효율 = 선택 상품별 뽑기 환산량 합계 × 3000원 / 전체 선택 가격 × 100. 효율의 단순 평균이 아니다.
- 선택권은 상품별로 환산하여 서로 다른 선택권/여러 선택권의 가치를 누락하지 않는다. 명시된 세트 완료 보너스는 해당 그룹의 구매 가능 상품을 전부 선택했을 때만 합산한다. 참고용/합계 행은 중복 합산하지 않는다.
- 합계 영역은 captureArea 안에 있어 체크 상품 PNG에도 포함된다. 모바일에서는 합계 카드가 줄바꿈된다.
- 변경 배포 파일: calculator/index.html, calculator/app.js, calculator/style.css. data.js 변경 없음.
- 검증: JS 구문, 선택 없음, 단일 상품 효율 일치, 복수 선택권, 세트 일부/전체 선택 보너스, 획득 수량 합산 검사 통과.


### 2026-10-14 구매 횟수 버튼

- 체크박스를 − / 현재 횟수 / + 버튼으로 변경. 직접 숫자 입력 없이 조절한다.
- 구독·월정액·패스·초회는 최대 1회. 나머지는 데이터 limit를 상한으로 사용하며 제한이 없으면 반복 증가 가능. 0회에서 감소 버튼, 최대 횟수에서 증가 버튼 비활성화.
- 총 가격·재화·나침반·선택권 환산량은 구매 횟수만큼 곱한다. 효율 공식은 유지. 세트 완료 보너스는 전체 구성 상품을 1회 이상 선택했을 때 한 번만 지급.
- PNG에는 1회 이상 상품만 포함하며 −/+ 버튼 대신 구매 횟수만 출력. 모바일 구매 횟수 영역 재배치.
- 변경: calculator/app.js, calculator/index.html, calculator/style.css. 데이터 수정 없음.
- 검증: JS 구문 검사, 1회 제한 상품, limit 상한, 0 하한, 반복 재화/티켓/선택권 합산, 보너스 1회, 동일 상품 반복 시 효율 불변 확인.
